Hugo와 GitHub Pages로 개발 블로그 구축하기

2026년 7월 12일

GitHub Pages를 이용하면 무료로 정적 웹사이트를 호스팅할 수 있다. 언젠가는 만들어야지 생각만 하다가, 이번 기회에 Hugo를 이용해 구축했다.

GitHub에서는 기본적으로 Jekyll을 안내하지만, Hugo로 이전하는 사례가 많아 Hugo를 선택했다.

이번 글에서는 Hugo와 GitHub Pages 환경을 구축하면서 진행한 과정을 정리한다.

1. Hugo 다운로드#

운영체제에 맞는 Hugo 실행 파일을 내려받아 환경 변수(PATH)에 등록한다.

  • https://github.com/gohugoio/hugo/releases

2. GitHub 저장소 생성#

Jekyll 은 소스를 그대로 배포하지만 Hugo 는 빌드 과정이 존재하여 소스 저장소와 배포 저장소를 구분하여 생성한다.

  • 소스 저장소 (Private) : username.github.blog
  • 배포 저장소 (Public) : username.github.io

저장소 생성 시 README.md를 함께 생성하면 초기 커밋을 따로 만들 필요가 없어 편하다.

3. Hugo 프로젝트 생성#

아래 명령줄을 실행하여 디렉토리 생성 후 저장소를 연결한다.

  • hugo new site 뒤에 오는 이름은 프로젝트 디렉터리 이름일 뿐이므로 호스팅과는 상관이 없다.
hugo new site username.github.blog

cd username.github.blog
git init
git remote add origin https://github.com/username/username.github.blog.git

4. 테마 및 Submodule 설정#

테마 추가#

Hugo는 다양한 테마를 제공한다.

  • https://themes.gohugo.io/

이번 글에서는 PaperMod 테마를 사용했다.

git submodule add https://github.com/adityatelange/hugo-PaperMod.git themes/PaperMod

배포 저장소 연결#

git submodule add -b main https://github.com/username/username.github.io.git public

빌드 결과물이 public 디렉터리에 생성되므로 GitHub Pages 저장소와 연결한다.

5. hugo.toml 설정#

baseURL = "https://username.github.io/"
languageCode = "ko-kr"
title = "username"
theme = "PaperMod"

[params]
assets.disableFingerprinting = true
  • baseURL : 블로그 주소를 입력한다.
  • languageCode : 사이트의 기본 언어를 설정한다.
  • title : 블로그 제목을 설정한다.
  • theme : 사용할 테마를 지정한다.
  • assets.disableFingerprinting : 최신 Hugo와 일부 테마 조합에서 발생하는 Integrity 오류를 방지하기 위해 추가했다.

6. 로컬 테스트#

hugo server -D

브라우저에서 http://localhost:1313으로 접속하면 수정 사항을 실시간으로 확인할 수 있다.

7. GitHub Pages 배포#

hugo

cd public
git add .
git commit -m "Deploy"
git push origin main

잠시 후 https://username.github.io에서 결과를 확인할 수 있다.

8. 소스 저장소 Push (최초 1회)#

  • .gitignore 파일을 생성한다.
    • public은 Git Submodule로 관리되므로 별도로 Ignore할 필요가 없다.
/.hugo_build.lock
/resources/
  • 소스 저장소 Push (최초 1회)
    • 저장소를 생성할 때 README.md를 만들지 않았다면 pull --allow-unrelated-histories 과정은 필요하지 않다.
git add .
git commit -m "Initial commit"

git branch --set-upstream-to=origin/main main
git pull origin main --allow-unrelated-histories
git push origin main

9. 다른 PC에서 프로젝트 이어하기#

다른 PC에서 작업할 경우에는 Submodule까지 함께 Clone 해야 한다.

git clone --recurse-submodules https://github.com/username/username.github.blog.git
  • 만약 일반 Clone을 했다면 아래 명령으로 Submodule을 내려받을 수 있다.
git submodule update --init --recursive

9. 게시물 작성#

  • 소스 저장소에서 아래와 같이 실행하면 각 폴더 하위에 파일이 생성된다.
    • 편집은 별도 편집 도구로 편집한다.
    • 꼭 아래 명령줄과 같이 생성하지않아도되고 다른 방법으로 파일을 생성해도된다.
  • 테스트 서버가 실행된 상태라면 파일을 저장할때 바로바로 테스트 서버에 반영되어 미리보기가 간편하다.
hugo new posts/1.md
hugo new posts/test/test1.md
hugo new posts/20260713.md

10. 소스 현행화 및 배포#

최상위 폴더에서 정적 파일 빌드 (public 폴더 갱신)#

hugo

배포 저장소(public)로 이동 후 반영 및 푸시#

cd public
git add .
git commit -m "Add posts"
git push origin main

다시 최상위 소스 폴더로 복귀 (포탈에서 빠져나오기)#

cd ..

public 연결 링크와 원본 마크다운을 소스 저장소에 최종 백업#

git add .
git commit -m "Add posts"
git push origin main
